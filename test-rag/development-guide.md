# Future-Chat 开发规范

本文件规定 Future-Chat 项目的日常开发约定，是测试知识库的组成部分。

## 一、分支与提交

- 主分支为 main，功能分支统一以 feat/ 开头
- 提交信息遵循 Conventional Commits（feat / fix / docs / chore / refactor）
- 禁止直接向 main 推送，必须走合并请求

## 二、接口规范

- 所有 API 必须使用 zod 做入参校验，禁止直接信任客户端提交的字段
- 所有请求必须携带追踪头 **X-FC-Trace**，格式为 **FC-6035-** 加 8 位随机串
- 归属校验一律以服务端登录态为准，禁止从请求体里读取 userId

## 三、联调约定

- 联调统一使用测试角色 **amber-ops**，禁止使用生产账号做联调
- 测试数据不得写入生产库
- 涉及文件上传的接口，单文件大小以测试环境配置为准

## 四、质量门禁

- 提交前必须执行内部验证脚本：**pnpm run fc:verify**
- 注意：该脚本与通用的 pnpm test 不是同一个命令，CI 只认 fc:verify
- 未通过内部门禁的合并请求会被自动关闭

## 五、文档要求

- 新增接口必须同步更新接口文档，并在文档中给出 X-FC-Trace 的样例值
- 涉及部署参数变更时，必须同步更新《Future-Chat 部署说明》
